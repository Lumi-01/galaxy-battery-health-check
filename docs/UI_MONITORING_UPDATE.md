# v0.5.2 · 배터리 사이클 체크

소스와 APK를 함께 배포합니다. 앱 이름을 **배터리 사이클 체크**로 바꾸고 versionCode를 10으로 올렸습니다. 기존 서명키와 applicationId를 유지하여 이전 앱 위에 업데이트할 수 있습니다.

## 화면과 색상

- One UI를 참고한 연한 회색 배경과 흰 카드에 민트·청록색 버튼을 사용합니다. 다크 모드는 검정에 가까운 배경, 짙은 회색 카드, 밝은 민트색 버튼입니다. 보조 버튼은 옅은 민트색 면으로 구분합니다.
- 잔량 막대는 양 끝이 둥근 민트 그라데이션입니다. 15% 이하에서는 주황색으로 바뀌며, 확인할 수 없는 값은 0%로 표시하지 않습니다.
- 토글은 파란 캡슐 스위치와 흰 손잡이입니다. 스위치 자체와 전체 행을 모두 누를 수 있으며 체크 상태와 스위치 접근성을 유지합니다.
- 하단 메뉴는 검정/밝은 글자와 아이콘, 회색 선택 캡슐을 사용합니다. 기록 분류 버튼에도 현재 선택한 항목을 구분합니다.
- 메뉴·설정 버튼의 GPU 블러 위에 반투명 유리색, 밝은 가장자리와 안쪽 반사선을 그립니다. 배경만 흐리고 아이콘과 글자는 별도로 선명하게 표시합니다. 정지 화면에 애니메이션 타이머를 추가하지 않습니다.
- 테마와 갱신 간격 선택은 둥근 팝업입니다. 라이트·다크 테마를 따릅니다.
- 메뉴 높이 64dp, 주요·보조·설정 버튼 높이 48dp를 유지합니다.

## 전체·코어별 그래프

기본 화면은 CPU와 GPU 전체 그래프입니다. CPU 코어별 스위치를 켜면 각 코어의 독립 그래프를 펼칩니다. 그래프 바로 아래에 클럭·사용률·온도를 같은 순서로 배치했습니다.

| 항목 | 측정 방식 |
|---|---|
| CPU 전체 사용률 | `/proc/stat` 집계 행의 차이. 집계 행이 없으면 모든 온라인 코어의 유효한 CPU 시간 차이를 가중 합산 |
| CPU 코어별 사용률 | 코어별 CPU 시간 차이. guest 카운터 중복 합산 제외 |
| CPU 클럭 | 현재 하드웨어 클럭 우선, 없으면 정책 요청 클럭. 전체 카드에는 읽은 코어들의 클럭 범위 |
| GPU 사용률·클럭 | KGSL 전체 percentage 또는 busy/total, gpuclk/devfreq 현재 클럭 |
| GPU 코어별 그래프 | 현재 조회 인터페이스에서 미제공. 코어별 옵션을 켜면 제한 안내 |
| CPU 코어별 온도 | 명시적인 cpuN/coreN 이름만 해당 코어에 매핑 |
| CPU·GPU 대표 온도 | 전체 온도 센서 우선, 없으면 해당 센서 최고값과 센서 이름 |

CPUFreq 클럭의 kHz와 GPU 클럭의 Hz를 각각 MHz로 변환합니다. CPU 정책 요청 클럭은 하드웨어가 실제 실행 중인 주파수와 다를 수 있습니다. 최대 지원 주파수를 현재 클럭으로 표시하지 않습니다. [Linux CPUFreq 문서](https://www.kernel.org/doc/html/latest/admin-guide/pm/cpufreq.html)

갱신 간격은 설정에서 1·2·5·10·30·60초를 선택하며 기본 2초입니다. 전력 기록과 기본 배터리 상태 간격은 별도로 유지합니다. 최근 120개를 표시하고, 미지원 값과 긴 공백을 선으로 잇지 않습니다. 화면을 벗어나면 하드웨어 조회를 정리합니다. 사용자가 시작한 충전·방전 기록 서비스는 계속됩니다.

## 센서별 온도

기본은 배터리·CPU·GPU 온도 요약이며, 센서별 스위치로 전체 목록을 펼칩니다. CPU·GPU·기타 그룹에서 이름과 온도를 정렬해 표시합니다. 같은 이름의 서로 다른 센서는 thermal zone ID도 표시합니다. 읽지 못한 값은 —로 표시합니다. SoC 센서를 임의의 CPU 코어 온도로 복사하거나 전체 온도를 모든 코어에 반복 표시하지 않습니다.

## 쓰로틀링 보완

OS 열 상태 변경 리스너를 추가하여 전력 기록 간격이 길어도 현재 단계가 즉시 반영되도록 했습니다. 기존 화면은 마지막 저장 샘플의 단계를 사용해, 60초 기록에서는 상태 변경 표시가 늦어질 수 있었습니다.

0단계는 **OS 제한 보고 없음**입니다. 실제 제한이 없다는 확정 표시를 제거했습니다. 일부 기기는 제한 중에도 0단계를 반환할 수 있습니다. 열 부하를 10초마다 추가 확인하고, 읽을 수 있는 CPU·GPU·주파수 제한 장치의 작동 상태도 함께 표시합니다. 열 부하 1.0은 심한 제한 기준이며 그 이상을 임의의 OS 단계로 환산하지 않습니다. 커널 제한 장치의 단계와 OS 0~6단계도 서로 섞지 않습니다. [Android Thermal API의 기기 제한](https://developer.android.com/games/optimize/adpf/thermal?hl=ko)

화면을 벗어나면 OS 리스너·열 부하 타이머·Shizuku 조회를 정리합니다. 연결이 늦거나 실패하면 접근 제한/시간 초과로 처리하고 잘못된 수치를 만들지 않습니다. 전력 기록 파일은 기존 형식과 OS 단계 저장을 유지합니다.

## 스크린샷과 검증

[README 화면 갤러리](../README.md#앱-화면)에 실제 에뮬레이터 화면과 예시 그래프를 넣었습니다. 예시 데이터 화면에는 **UI 예시 · 샘플 데이터** 표시가 있습니다. 실제 S25 측정 화면으로 제시하지 않습니다. 예시 데이터를 만드는 검증용 APK는 배포 APK에 포함하지 않습니다.

- 값 처리·로그·전력·기록·하드웨어·열 부하 해석 169개 검증 통과.
- Kotlin 컴파일, APK 패키징·서명·정렬·매니페스트 확인.
- Android 15 에뮬레이터에서 8개 독립 CPU 그래프, 하단 수치, 센서 그룹과 스위치 화면을 검증용 예시 데이터로 확인.
- 실제 UI에서 스위치 켜기/끄기와 접근성 체크 상태, 테마 선택 팝업, 라이트·다크 전환, 기록 분류 선택 색상과 GPU 미지원 안내 확인.
- 전력 기록 간격을 60초로 설정하고 OS 열 상태를 3→0단계로 바꿔, 저장 샘플을 기다리지 않고 화면에 즉시 반영되는지 확인.
- 실제 갤럭시 센서 접근, Shizuku 응답, Android 16/One UI 라이브 칩은 실기기 확인이 필요합니다.

주요 코드는 `HardwareMonitorView.kt`, `HardwareTelemetry.kt`, `HardwareProbe.kt`, `UsageGraphView.kt`, `ThermalMonitor.kt`, `OneUiToggle.kt`, `OptionPicker.kt`, `LiquidGlassEdge.kt`에 나누어 두었습니다. [코드 위치·빌드 안내](DEVELOPMENT.md)
